## 一、教学有效性质疑

**结论：不能把“fail 后自动推两道同构题”设为默认复习策略。它适合作为短期补救，却不能替代间隔后重做原题；连续两道同构题尤其容易训练出模式匹配，而不是真正迁移。**

学生刚看过解法后，工作记忆里还留着结构和技巧。此时连续做两道同构题，成功往往只说明“会照着套”，并不说明下次能在没有提示、题型混杂时识别该结构。把同类题成组呈现，本身就在泄露“应该用同一种方法”这一元提示。

更合理的动作是：

1. fail 当天：看解法后合卷复述，定位失败环节——读题建模、结构识别、关键引理、技术执行还是证明表达。
2. 24–48 小时后：做一道近迁移变式，检验能否重建刚学的方法。
3. 7–14 天后：从零重做原题，检验长期提取。
4. 更晚且混题环境下：做一道表面不同、核心方法相同的远迁移题，检验是否真的会选方法。

因此，原题重做和变式训练不是二选一：

- 原题重做测“是否记住并能重新组织”；
- 同构变式测“近迁移”；
- 混合专题中的远变式测“方法选择和真正迁移”。

现有研究方向支持间隔重学和混合练习，而不是连续刷同型题。连续多次、跨时间的重新提取有明显长期保持优势；数学练习中，混排同样的问题曾将延迟测试成绩从 38% 提高到 61%，关键就在于学生必须自己选择方法，而不是从题组顺序中获得提示。[successive relearning 研究](https://pubmed.ncbi.nlm.nih.gov/29431462/)，[数学混合练习随机研究](https://nces.ed.gov/use-work/awards/efficacy-study-interleaved-mathematics-practice)

专题爬梯有真实价值，但当前设想把它说得过于自动化。真正有效的爬梯应逐步增加“推理跨度”和撤除脚手架，而不是简单按现有星级排序：

- ★2 掌握工具；
- ★3 在明确专题语境中选择工具；
- ★4 在弱提示或跨知识点题中识别隐藏结构；
- 最后一题应是对照题或远迁移题，不能仍是同模板换数字。

同一个 embedding cluster 未必覆盖完整难度梯度；即使覆盖，难度差也可能来自计算量、附加引理或表达要求，而不是同一能力的递进。**专题爬梯值得做，但必须由“教学目标—前置技能—方法变化”定义，不能由相似度排序冒充课程设计。**

还有一个必须先修的事实：手册声称“连续两次 ok 毕业”，但代码只保留每题最后一条记录，没有计算连续成功次数，也没有毕业状态；`ok` 会每 21 天永久重新出现。[bank.py](/Users/Apple/Developer/GitHub/olympiad-bank/scripts/bank.py:236) 当前 review 设计并未实现文档宣称的学习规则。

## 二、技术选型审查

**结论：MiniLM 可以做低成本候选召回，不能直接产出可信的 `cluster_id`，更不能用固定的 0.95 阈值宣判重复。当前设计把通用语义相似、题目同构和解法同类混成了一个数，这是技术上的根本错误。**

### 1. MiniLM 不足以承担“同解法”判定

`paraphrase-multilingual-MiniLM-L12-v2` 是通用句段相似模型，384 维，而且最大序列长度只有 128 token。[官方模型卡](https://huggingface.co/sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2) 奥数题的区别经常藏在量词、退化条件、指数、模数或几何位置关系里；这些恰好可能在截断后丢失，也不是通用 paraphrase 训练重点。

更直接的反证来自 MathNet 自己：在 10,000 个带人工等价关系的检索锚点上，明显更强的 embedding 模型 Recall@1 仍全部低于 5%；最强结果也只有约 4.96%，虽然 Recall@5 可到 65%–69%。[MathNet 检索基准结果](https://mathnet.mit.edu/) 这说明 embedding 适合生成 top-k 候选，尚不适合自动把第一名当成“同构题”。

所以必须先跑 MathNet 已发布的 retrieval benchmark，再谈选模型和阈值；不应凭 CPU 时间和模型名拍板。

### 2. 不应存单一 cluster，应存“带类型的相似边”

“重复”“同构”“同解法”“同专题”不是一条可安全切段的单轴光谱，而且相似关系未必可传递：

- A 与 B 同构；
- B 与 C 共享一个技巧；
- 不代表 A 与 C 属于同一教学组。

图聚类还会出现阈值链式合并，最终一个 cluster 内首尾题并不相似。正确数据模型应是：

```text
source_id, target_id
relation: duplicate | near_isomorphic | same_method | related
confidence
evidence: text | formula | solution_method | metadata | human
review_status
```

`bank.py similar` 应返回“为什么相似”的 top-k 边，而不是声称它们天然属于同一个稳定 cluster。

### 3. 节点桶应作召回加权，不能作硬边界

按“节点×板块”硬分桶会提高精度，却会系统性漏掉跨标签关系。当前候选中有 7,333 题投中了多个板块，1,667 题只有弱知识点，另有 136 道 `ok` 题没有节点。库内题经规范节点归并后，44 个有题节点的桶中位数仅 7 题，8 个桶最多两题。硬分桶既会漏召回，也会产生大量无法聚类的小桶。

应使用两路召回的并集：

- 全库 ANN/top-k，发现跨节点与错标签关系；
- 同板块、同节点或相邻节点召回，并给予先验加分。

topic 是特征，不是围墙。

### 4. 公式与文本不要先粗暴线性混成一个权重

公式特征的作用随任务不同：

- 查重复：公式、数字、变量结构、赛事年份应高权重；
- 查换皮同构：变量改名和常数变化应弱化，但关系结构应保留；
- 查同解法：题面公式可能完全不同，强加公式权重反而伤害召回。

因此应先计算独立特征，再由关系类型分别判定：

- 规范化文本 hash、字符 n-gram：近重复；
- 公式 AST/运算符序列、变量改名规范化：结构相似；
- 通用或数学 embedding：语义候选召回；
- solution 方法签名：教学同类；
- contest、topic、difficulty：先验和排序特征。

仅提取 `$...$` 也不够，会漏掉 `$$...$$`、`\(...\)`、`\[...\]`、`align` 等环境，并会被 OCR 与 LaTeX 写法差异干扰。

### 5. 按 solution 聚类方向更正确，但不能直接嵌入全文

本地数据说明 MathNet 解答确实值得利用：实际解答长度中位数约 899 字符，只有 3,535 条为空。但当前 `mathnet_ingest.py` 的 `sol_chars` 写成了 `len(solutions_markdown)`，测到的是“解答条数”而非字符数，因此几乎全部显示为 1–4。[mathnet_ingest.py](/Users/Apple/Developer/GitHub/olympiad-bank/scripts/mathnet_ingest.py:284)

应先从每个解答抽取短小的、可审计的方法签名，例如：

```text
不变量：2×2 子块奇偶性
关键结构：三周期
推进方式：局部约束 → 全局周期
```

一道题有多个解法时，应允许多个方法签名。solution embedding 用于召回“同方法”，题面 embedding 用于召回“同叙述/同结构”，二者不能压成一个向量。

规模本身不是瓶颈：约 2.8 万个 384 维 float32 向量只占约 43 MB。真正昂贵的是人工标注、关系校准和误推荐成本。**计算 20 分钟不等于系统在 20 分钟后就可信。**

## 三、优先序审查

**结论：spar 先于聚类是对的，但“spar → 聚类 → 盲陪练”仍然过度设计。attempts=0 时，最高优先级不是扩大推荐能力，而是证明一个学生愿意完成一次训练闭环，并把过程数据可靠地留下。**

目前最大的风险不是“找不到相似题”，而是：

- 没人使用；
- 训练流程摩擦过大；
- 结果分类含糊；
- 文档规则与代码不一致；
- 没有数据说明学生究竟在哪里失败。

现有日志只有 `result/hints/note/date`，缺少：

- 实际用时和暂停时间；
- 提示逐级解锁时间；
- 是否看过答案；
- 首次错误或卡点类型；
- 是否完成了合卷复述；
- 证明是完整、缺口还是仅有想法；
- 这是首次攻坚、原题复习还是变式迁移；
- session ID 和尝试序号。

没有这些字段，聚类推荐即便正确，也无法判断是否提高了学习效率。

D1 应该先做，但必须极简：一条命令显示无答案题卡，结束后按需解锁提示、答案并自动记录。所谓“隔离目录”只能防止无意剧透，不是真正的答案隔离；后续 Codex 若有父目录、搜索工具或网络能力，仍可能取到答案。盲陪练需要能力级沙箱，而不只是换工作目录。

优先序应改成：

1. 修正 review 状态机和日志语义；
2. 做最小 spar；
3. 跟一个真实学生完成 8–12 次训练；
4. 根据失败数据人工配几组变式；
5. 验证有收益后再自动检索；
6. 盲陪练只在基础闭环稳定后接入。

聚类不应排在真实使用数据之前。否则很可能做出一个精致的 `similar` 命令，却仍有 0 条 attempt。

## 四、修正版两周方案

**结论：两周内砍掉全量自动聚类、永久 `cluster_id`、0.95 去重阈值和自动专题爬梯。交付目标只定为：一个学生能无剧透地训练、系统能可靠记录、一次 fail 能触发经人工确认的近迁移与延迟复习。**

### 第 1–3 天：把现有闭环修到名副其实

- 修复“连续两次 ok 毕业”，保存成功次数和毕业状态。
- 删除 review 重复打印纪律的代码错误。
- 增加 `session_id`、开始/结束时间、实际用时、提示事件、答案揭示、训练类型。
- 把结果拆成：
  - `independent_ok`
  - `hinted_ok`
  - `solution_reconstructed`
  - `fail`
- 增加简单卡点标签：`建模 / 识别结构 / 关键引理 / 技术执行 / 证明表达`。
- 所有日志保持追加式，并让派生状态可重新计算。

### 第 4–6 天：做最小 spar

只实现四个动作：

```text
spar start <ID>
spar hint
spar reveal
spar finish
```

题卡只含题面、纸笔限时和 session ID；提示逐级解锁；`finish` 自动记录，不要求学生另记一条 `bank.py log`。默认流程要减少操作，而不是仅把纪律写在手册里。

选 12–20 道适合该学生当前水平的题，不追求覆盖全库。先观察：

- 是否能独立开始；
- 是否知道何时请求提示；
- 是否愿意回来完成记录；
- 一次训练总摩擦时间。

### 第 7–10 天：人工建立一个小型“教学相似图”

只围绕该学生最常失败的 2–3 个方法，人工确认约 20–40 条关系边。每组至少包括：

- 原题；
- 一道近迁移变式；
- 一道容易混淆但方法不同的对照题；
- 条件允许时，一道远迁移题。

用 MathNet embedding 只生成 top-20 候选；不要自动成组。优先利用题面 embedding、公式结构和 solution 方法摘要共同排序，由人确认关系类型。MathNet 官方 benchmark 已经证明，top-5 候选有价值，而 top-1 自动判断不可靠。

### 第 11–14 天：跑一个可测量的学习周期

对一次 fail 执行：

```text
当天：解法复述 + 卡点记录
+2 天：近迁移变式
+7 天：原题从零重做
+10～14 天：混排环境中的远迁移/对照题
```

两周只看四个结果：

- 学生是否完成至少 8 次 session；
- 日志完成率是否超过 80%；
- 原题延迟重做是否独立成功；
- 近迁移和远迁移是否分别成功。

`similar` 的最小版本可以做，但输出应是：

```text
关系类型 / 置信度 / 相似依据 / 是否人工确认
```

而不是 `cluster_id`。

只有当人工抽检显示“同方法”top-5 精度足够高，并且真实学生确实从变式流程中获益，第三周以后才值得扩展全库索引、自动采购定位和专题爬梯。**两周的成功标准不是聚完 27,481 题，而是让第一个学生留下可信的学习轨迹，并证明系统改变了下一次练习选择。**
