# 教练手册

题库不只是档案，是训练系统。完整闭环：**定目标 → 出周计划 → 限时攻坚（提示阶梯纪律）→ 记录 → 间隔复习**。学生侧的一页流程见 `docs/学生手册.md`。

## 1. 定目标，出周计划

```bash
uv run python scripts/bank.py plan --target CMO --n 10              # 先预览一周配额；库存不足会逐档提示
uv run python scripts/bank.py coach --target AIME --weeks 4 --n 10   # 生成 4 周训练计划
uv run python scripts/bank.py coach --target CMO --seed 2            # 换 seed 换一套
uv run python scripts/bank.py coach --target IMO --save              # 第 1 周写入 data/plan.json，spar next 按此出题
```

`plan` 适合先检查一周配额与库存；`coach` 再按目标赛事的星级配比 + 四板块轮转生成多周计划，
自动跳过已做过的题，并在结尾附上当前复习队列。需要补足缺口时转到
`docs/入库SOP-MathNet.md`。

不惯用命令行的教练可在浏览器训练台（`uv run python scripts/bank.py web`）的「教练工具」里生成周计划——同一套选题逻辑（`bank.py` 的配比与轮转函数），写的也是同一份 `data/plan.json`，只做第 1 周。

## 2. 攻坚纪律（核心）

<!-- training-contract:time-limits:start -->
- **限时独立攻坚**：★1≤15min，★2≤25min，★3≤40min，★4≤80min，★5≤120min。限时内不看任何提示。
<!-- training-contract:time-limits:end -->
- **提示阶梯**：每道题文件末尾有三级提示（由 Codex 从本题《解法要点》导出，入库时同批补齐）——
  - 提示 1（方向）：只指出该往哪看，不给结构；
  - 提示 2（关键结构）：给出核心引理/模型，不给推理；
  - 提示 3（临门一脚）：给到差最后一步。
  <!-- training-contract:hint-cooldown:start -->
  卡住时**逐级**解锁，每解一级再独立奋战 15 分钟。跳级＝浪费一道好题。
  <!-- training-contract:hint-cooldown:end -->
- **看答案的时机**：提示 3 之后仍无进展，或超时 2 倍——看解法要点，然后**合上文件复述完整证明**。
- 纪律是默认值不是墙：提前解锁、超时都不会被阻止，只提醒并打上 `early` 标记进日志，供事后诊断。

## 3. 记录

日常训练走 `spar` 四动作（start/next 开卡、hint、reveal、finish），`finish` 自动追加一条记录到 `data/attempts.jsonl`，不需要学生另跑一条命令；`log` 保留作 spar 之外的手工补记。结果四分：

| 结果 | 判定标准 |
| --- | --- |
| `independent_ok` | 未看答案，提示 ≤1 级，限时内独立完成 |
| `hinted_ok` | 未看答案，但用到第 2/3 级提示或超时完成 |
| `solution_reconstructed` | 看了答案（reveal 过），随后合卷复述通过 |
| `fail` | 看了答案，复述未通过（或未做复述） |

`finish` 按会话事实自动建议：reveal 过 → 询问「合卷复述通过了吗」，通过＝`solution_reconstructed`，否＝`fail`；未看答案且提示 ≤1 级且未超时 → `independent_ok`；其余 → `hinted_ok`。学生可改判。同时记一个卡点标签（五选一）：`建模 / 识别结构 / 关键引理 / 技术执行 / 证明表达`。

旧三分记录（ok/hard/fail + 整数 hints）读取时自动归一化：ok 且提示 ≤1 → `independent_ok`，ok 且提示 ≥2 → `hinted_ok`，hard → `hinted_ok`，fail → `fail`，不需迁移文件。

## 4. 间隔复习

```bash
uv run python scripts/bank.py review
```

按最近一次结果进入队列：

<!-- training-contract:intervals:start -->
| 最近结果 | 间隔 |
| --- | --- |
| `independent_ok` | 21 天 |
| `hinted_ok` | 7 天 |
| `solution_reconstructed` | 3 天 |
| `fail` | 2 天 |
<!-- training-contract:intervals:end -->

<!-- training-contract:graduate-streak:start -->
复习时**从零重做**，不先看提示。**毕业规则**：同一题连续 2 次 `independent_ok` 即毕业，永久退出复习队列；`review` 输出单列「🎓 本次毕业」名单。fail 后队列会按上表在 +2/+3 天弹出原题做短间隔重建检查，长期提取由后续周期（`hinted_ok` 7 天、`independent_ok` 21 天）自动覆盖；除此之外还有一组教练主动安排（当天复述 → +2 天近迁移变式 → +10–14 天混排远迁移），见 `docs/学生手册.md` 第 4 节。
<!-- training-contract:graduate-streak:end -->

变式与远迁移题从相似边台账里挑，工具链：

```bash
uv run --group similar python scripts/similar_index.py build --bank-only   # 相似索引（建一次即可）
uv run python scripts/bank.py similar A-001                                # top-k 相似候选
uv run python scripts/bank.py similar A-001 --confirm MN-06nq --relation same_method   # 确认边写入 data/similar/edges.jsonl
```

## 5. 学生档案与能力图

每个学生一份档案：四板块基础值（若干波测评打底）＋ 知识点级能力图，最终目标是把各板块补齐。

### 建档与测评波次

```bash
uv run python scripts/bank.py student add zhang-san --name 张三 --grade 初二 --target AIME
uv run python scripts/bank.py student list
uv run python scripts/bank.py assess zhang-san --wave 基线-1 --id A-003 --score 1        # 库内题：板块/知识点/难度自动带出
uv run python scripts/bank.py assess zhang-san --wave 基线-1 --source "AMC10 2023 P15" \
  --category combinatorics --difficulty 2 --topics 图论 --score 0.5                      # 外部题：四件事手填
uv run python scripts/bank.py profile zhang-san --html    # 能力图：终端报告 + maps/能力图-zhang-san.html
```

若某位学生的历史 spar 日志使用 `student=self`，建档时用 `--alias self` 绑定；这些记录会自动
归入其证据流，让测评与日常训练两路证据合流进同一张能力图。

### 能力图怎么读

证据折算与状态阈值的**正本在 `scripts/student_profile.py` 模块 docstring**（SPEC §7 已登记），此处只说读法：

- **基础值走势**：每波测评按板块算难度加权掌握率，波次成序列，就是「若干波考试测基础值」；
  「全部证据累计」行是测评＋训练合并后的当前值；
- **节点状态四档**：⬜ 未测 / ⚠️ 薄弱 / 🔶 进行中 / ✅ 稳固；「已证★n」= 有满分证据的最高难度；
- **补齐队列**：薄弱优先、未测在后，每个缺口给 ≤2 道库内没做过的题；
  库内无题的缺口走 `candidates --gaps` 采购扩容——补齐板块从这里闭环；
- **补的顺序看前置**：同档缺口按知识点前置依赖排序，先补最上游（边的正本
  `taxonomy/prereq.yml`，头注有语义；指示图 `bank.py map` 的节点卡上有「前置 →」可视化）；
  队列项标注「先补：X」时，意思是这个缺口的前置本身也薄弱——从 X 打起，别硬灌下游。

### 分类细分：AI + 教练按案例迭代

节点粒度不预设，靠案例摸出来。某节点对某学生「强弱分化」（证据 ≥ 阈值且强弱两极都有）时，
`profile` 会点名该节点并列出强弱案例——这就是「分类过粗」的信号。迭代流程：

1. 教练与 AI 一起读这些案例，找出分化的真实维度（例：图论 → 度数/连通性论证 vs 极值图论）；
2. 在 `taxonomy/registry.yml` 细分：细分写法先登记为别名试用，站得住再立为节点
   （同时补 `taxonomy/<板块>.md` 小节，doclint 强制树一致）；
3. retag 相关题目的 `topics`——历史证据读取时按现行 frontmatter 解析，
   自动落到细分后的节点，**不需要迁移任何历史数据**。

另有一类缺口不是「题不够」而是**标签器盲区**：`bank.py candidates --gaps` 里「库内 0 题、候选也 0 题」
的节点，多半是 MathNet 标签树没有对应叶子（如「数字与进位制」「组合构造」），入库时标签器
产不出这个节点名，于是题在库里、节点却空着。处理方式是读题 retag，而不是继续采购：

- 判据从严——该节点必须是**解题主线**，题面里出现同名词汇不算；
- 做法上让 AI 先提议（附题面/解法原文摘录），再让另一路 AI **专门尝试驳倒**，只采纳驳不倒的；
- 供给侧同步补 `taxonomy/mathnet_map.yml` 的 `keyword_rules`，下次重建候选池就能自动召回。

节点库存会随新批次入库变化，手册不固定某节点的题数或「仍为空」结论。判断当下缺口时运行
`uv run python scripts/bank.py candidates --gaps`；候选池不存在时，按 `CLAUDE.md` 的重建指引处理。

## 6. 教练观（为什么这样设计）

- 提示阶梯模拟真教练的「递进式点拨」：先救方向，再救结构，最后救细节——最大化每道题的训练价值。
- 限时表按赛制标定：AIME 单题均时 ≈12min，但训练题偏难一档，故上浮；CMO/IMO 单题 90-120min 是实战节奏。
- 提示用量与卡点标签是诊断金矿：某板块「识别结构」标签占比高 ⇒ 该环节薄弱，下轮计划应加该板块 ★-1 档的题补基本功。
- 日志 v2 字段已就绪：session、逐级提示时间（含 early 标记）、revealed_at、卡点标签、实际用时、fresh/review/variant 训练类型全部落盘。`data/attempts.jsonl` 积累 ≥50 条后，即可让教练（Claude）读日志出诊断报告与自适应计划。
